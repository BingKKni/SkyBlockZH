# SkyZH — 技术文档

> **这是面向开发者的技术文档。** 它描述翻译引擎的内部实现——渲染面、Mixin、语料格式，
> 以及用于换行和居中的像素测量。如果你是玩家，想了解这个 Mod 有什么用、怎么安装，
> 请看[主 README](../README.md)。

[中文](TECHNICAL_zh-CN.md) · [English technical documentation](TECHNICAL.md)

Hypixel SkyBlock 中文翻译 Mod。Minecraft 26.1.x、26.2 与 26.3 / Fabric，仅客户端——一套源码，
每个 Minecraft 一个 jar，见[构建](#构建)。

SkyBlock 没有官方中文，中文玩家要么花时间啃英文，要么截图分享给朋友时对方看一眼就划走。这个 Mod
把游戏里的文本换成中文，目标是让没玩过的人也愿意读下去，让新手不用先学词汇才能上手。

## 默认档与其他 Mod 的兼容

显示优先级默认为 `default`，保留以下兼容行为。`high` 和 `force` 是用户主动选择的显示兼容排错模式；
高档与强制档会绕过部分辅助 Mod 的显示修改，但仍不改服务器数据或向服务器发送译文。

翻译**只发生在文字被画到屏幕上的那一刻**，游戏状态一个字节都不改：

| 其他 Mod 读到的 | 状态 |
|---|---|
| `ItemStack` 的名称与 Lore 组件 | 英文原文 |
| 聊天历史 `allMessages` / 复制到剪贴板的内容 | 英文原文 |
| `Screen#getTitle()` 容器标题 | 英文原文 |
| `BossEvent#getName()` | 英文原文 |
| `Hud` 的 `overlayMessageString` / `title` / `subtitle` | 英文原文 |
| `Objective#getDisplayName()` 与 `Scoreboard` 里的计分板条目 | 英文原文 |

所有解析聊天的 Mod 都工作在网络包处理或 Fabric 的聊天事件上，那都在本 Mod 的注入点**之前**，
所以 SkyHanni、SkyBlocker 看到的永远是 Hypixel 原样发来的英文。这不是附带效果，是设计目标：
一个让 SkyHanni 失效的翻译 Mod，对绝大多数 SkyBlock 玩家来说比读英文更糟。

运行时翻译入口先经过 `HypixelServer.canTranslate()`，再读取译文缓存、查词表或重算布局。
Tooltip 在原文模式下仍检查服务器边界与总开关，只为追加恢复翻译提示而确认物品名称覆盖，不输出译文或重排原始 Lore。
连接地址不再参与判断：国内加速器通常会把 `hypixel.net` 换成加速 IP 或本地中转地址。现在必须同时
满足两份来自服务器的实时证据——当前连接上 Hypixel 自报了身份（官方的 `hypixel:hello` 数据包，
或者标准 `minecraft:brand` 里写着 `Hypixel BungeeCord`，后者也是 SkyBlocker 用的判据），并且侧边栏
objective 的内部名是 `SBScoreboard`（SkyHanni 判定 SkyBlock 计分板用的就是这个名字；不看显示标题，
标题带跑马灯高亮、图标和 `CO-OP`/`GUEST` 后缀，换个样式就会失配）。前者挡住其他服务器和仿 SkyBlock 服务器，后者挡住 Hypixel 的其他玩法。
这两个数据包都是在数据包自己的 `handle` 上读的，不在监听器的方法上：Fabric API 会对任何被 Mod
注册过的载荷类型取消监听器方法，而 `hypixel-mod-api` 恰好注册了 hello，装了 SkyHanni 或 SkyBlocker
的客户端上，监听器钩子永远看不到它。
非 Hypixel、单人世界和主界面直接沿用原版文本与坐标；切换进出 SkyBlock 时会重建聊天显示行，
更换网络连接则先清空两份证据，避免上一台服务器的放行状态残留。这个限制与采集开关无关。
纯语料匹配引擎及 `locate` 不依赖服务器，仍可供离线自检和采集分类使用。

所有注入点都使用 `require = 0`，允许缺失的注入点只让对应渲染面停止翻译，不因最低注入次数检查而报错。
启动日志里会打印各类目实际加载了多少条记录。

包装调用的钩子使用 MixinExtras 的 `@WrapOperation`，不用 `@Redirect`。`@Redirect` 会争夺同一条指令的独占权，
冲突落败的必需钩子可能导致启动失败。`@WrapOperation` 支持与其他钩子（包括 `@Redirect`）串联，
`checkMixinTargets` 会检查配置中的 Mixin 是否使用了 `@Redirect`。

原文热键提示只观察收到的服务器聊天包，不改包、不发包，也不在聊天历史重排时重复提示。
下面「[运行时采集](#运行时采集默认关闭)」是另一个默认关闭的路径，用来补语料；它同样不改包、
不改游戏状态或显示。只有打开采集时才可能订阅 Hypixel 自己的位置事件，
见下面「[唯一一处会向 Hypixel 发包的东西](#唯一一处会向-hypixel-发包的东西)」。

## 三个已知问题是怎么解决的

**居中错位.** Hypixel 用空格把文本凑成居中，空格数是按英文像素宽算的，换成中文就右边空一大截。
本 Mod 直接丢掉原有空格重算：容器标题、BossBar、动作栏、标题/副标题这几处 Mod 自己决定绘制坐标，
按译文真实像素宽重算，**精确到像素**；聊天横幅只能靠空格填充（一个空格 4px，误差约 ±2px），
但那也正是 Hypixel 自己那套居中术在英文下的精度，没有比原版更差。

**Lore 排版参差.** 保持和英文原版一样的左对齐（这是明确选择，不是没做）。真正要处理的是另一件事：
英文因排版被拆成两行的整句，在语料里合并成一条完整逻辑句翻译，渲染时把作为"尾巴"的那一行删掉，
并按客户端字体像素宽对合并后的中文重新折行（中文断行不看空格，CJK 字符间几乎处处可断，
但不会把句号、右括号之类甩到行首）。首行若尚未翻译，尾行原样保留——半句中文接半句英文是最糟的结果。

**颜色失真/丢失.** 一行 SkyBlock 文本经常中途换好几次色，切换点和句子结构对不上。语料用 `segments`
数组按颜色把原文分段，每段带自己的译文；渲染时**从屏幕上的实时文本读每一段的真实颜色**，
而不是信任语料里记的颜色码——记录是快照，Hypixel 一次更新就可能过时，而正在渲染的那行永远不会。
占位符捕获到的内容（玩家名、物品名、数值）连同它自己的颜色原样搬过去。若某条记录在实际游戏里
有多段颜色但语料只记了一整行，日志会点名该条记录提醒补 `segments`，同时仍按第一段颜色渲染。

### 动作栏是一排部件，不是一句话

SkyBlock 的动作栏中间那一行其实是它自己的 HUD：血量、所在地、法力、防御、以及临时顶上来的经验
提示，五个空格隔一格并排画在一起——

```
2,610/2,235❤     ⏣ 升降梯     469/469✎ 400⸕     104/104♨
```

整行去查表永远查不到，因为里面每个数字都随玩家走动在变，两帧之间就是两句不同的"话"。所以渲染前
先按**宽间隔(≥3 个空格)**把它切成部件，每个部件各查各的表，中间的空格原样放回去——那是 SkyBlock
自己量好的排版，中文部件仍旧落在英文部件的位置上。整行**先**试一次:哪条记录把整行写出来了，
那条说了算，所以服务器居中过的单条动作栏消息不受影响。

同一套切法也用在采集上。切之前一次会话采到八百多条只有数字不同的整行记录，切之后是十几个短部件，
其中一半是"数字加一个图标"、压根没有词，采集器自己就不收了。

### 计分板与"闪动"

侧边栏是全游戏唯一真会逐帧变化的表面：Hypixel 每 tick 重发一次 objective 的显示名，纯文本恒为
`SKYBLOCK`，变的是逐字符颜色——一道高光在字母间扫过，这就是那个闪动效果。两处配合才能保住它：

- **按完整文本和实时样式缓存渲染结果**。内容、颜色、字体、交互样式及行边界全部相同才复用；
  颜色变化立即生成新结果，跑马灯不会被冻结。缓存有容量上限，配置或资源重载时失效。
- **逐字符摊分颜色**。8 个字母变 4 个汉字，若统一取首字母的颜色，扫动会退化成整词闪烁。
  所以每个汉字从它所代表的那段字母里取色；又因为一个汉字盖两个字母、一格宽的高光会有一半帧落空，
  取色时优先取该段里**不同于全词主色**的那个，于是高光不会被丢掉，只是每个位置停留两帧。

注入点也特意选在**读取文本**处而不是绘制处：`displayScoreboardSidebar` 要先量标题和每一行的宽度，
才能决定面板多宽、左边界在哪、标题居中从哪开始。在源头翻译，这些测量量的就是中文；
在绘制处翻译，面板会按英文尺寸裁好、中文塞在里面对不上。

## 设置

Mod Menu 是软依赖。没装也能用，改 `config/skyzh.json` 即可，文件里带中文说明。

| 选项 | 默认 | 说明 |
|---|---|---|
| `enabled` | 开 | 总开关。关闭后不翻译任何文本，也不启动更新检查 |
| `updateCheck` | 开 | 进入空岛生存后自动检查并下载 Mod 与翻译更新；翻译立即生效，Mod 退出后安装。`/skyzh updatecheck on/off` 控制自动更新；省略参数主动先检查 Mod 再检查翻译包，`mod` / `translate` 只检查对应更新。主动检查跳过自动开关及冷却，但仍需总开关和空岛环境；所有别名共用忙状态 |
| `updateChannel` | `release` | Mod 更新渠道。`release` 只看正式 Release；`beta` 只看 Actions 每次提交构建的测试版。设置页把它与 `updateCheck` 合成「检查更新：关闭／正式版／测试版」 |
| `updateInstall` | `auto` | 发现新版 Mod 后：`auto` 下载并在退出后安装；`manual` 下载后在聊天栏发 `[点击安装]`；`notify` 仅发 `[点击下载并安装]`。后两者每次检查（约一小时）都会重新提醒，有更新的版本时先替换已下载的包。翻译包不受影响 |
| `translateSkyBlockName` | 开 | 把 SkyBlock 译作「空岛生存」。复合词里自动用简称并修正空格：`你的 SkyBlock 等级` → `你的空岛等级`，`+150 SkyBlock XP` → `+150 空岛经验`；独立出现仍用全称。尚未翻译的英文句子里也生效，但**有条件**，见下面「在哪替换、在哪不替换」 |
| `translateItemNames` | 开 | 关闭后真实物品名及其在 NPC／系统消息、悬浮文字、菜单和 Lore 中的明确引用保留英文，其他内容继续翻译。固定引用使用 `item_refs`，动态引用复用物品占位符；不改变服务器原文或采集覆盖判断 |
| `translateMobNames` | 开 | 关闭后生物名保留英文：头顶血条名、`mob_name` 占位符、`raw`／`category_name` 等占位符及 Tab 行中命中 `mob_name` 词表的值，以及语料用 `mob_refs` 标出的固定引用。宠物、兔子、碎片等借用生物名的占位符写 `"mob": false`；`Terms.json` 的 `not_creatures` 列出在非生物占位符里指职业、阵营、宠物的词。与物品名开关互不影响 |
| `legacyFont` | 开 | 「文本间距」。开启时在客户端资源重载里叠加内置的 1.12.2 Unicode 字形与字宽（`skyzh_legacy_font/`，等同置顶的资源包），逗号、句号等按 1.12.2 实际宽度绘制；关闭为原版全角。切换后关闭设置页时重载资源 |
| `originalTips` | 开 | 「翻译提示」：GUI 中已翻译的真实物品在 Lore 末尾提示当前原文热键；服务器聊天提到符合条件的已翻译物品时提醒，间隔至少 5 分钟，可点击禁用。`ItemNames` 使用内置离线 NEU 名称目录，排除菜单、状态与未知名称。`/skyzh switch tip on/off`（或 `/skyblockzh`）控制提示，不影响原文切换键。旧 `showOriginal` 不再读取或保存，缺少新字段时默认开；普通显示不再追加括号原文 |
| `helpImproveTranslation` | 开 | 旧配置兼容的预留状态，当前无对应界面控件或报告功能 |
| `captureUntranslated` | **关** | 给补语料的人用的开发者开关，会往硬盘写文件，普通游玩请保持关闭。见下面「运行时采集」 |
| `captureNotifications` | 开 | 采集文本提示。是否在聊天栏报告新采集的未翻译、颜色、中英混杂、排版、跨行及数值问题 |
| `autoClearCapture` | **关** | 「自动清空已采集文本」：客户端每次启动时清空上一轮采集，不依赖进服或采集总开关；断线重连不会清空 |

设置页使用 MoulConfig（与 SkyHanni、Skyblocker 默认设置页相同的界面库）：标题栏「SkyZH <版本> Beta」，左侧为通用／翻译／高级分类，右上角搜索框按选项名和说明过滤，空分类自动隐藏。每个选项一张卡片，开关与下拉框在左侧、说明在右侧；中文说明复用 `TextLayout` 折行，不缩小字号。「安装更新方式」仅在检查更新不为关闭时出现。高级分类中「显示优先级」与「采集」各为一个可折叠块。总开关关闭时其余选项变灰且不可操作。旧配置缺少新字段时采用上表默认值。
Mod 不依赖 Fabric API：`ResourceManagerMixin` 在客户端资源重载时把 Mod 自身的 `assets/`（语言文件）放在原版之上，并按 `legacyFont` 叠加字体包。
首次安装后，客户端首次确认进入 Hypixel 时会在聊天栏发送欢迎消息。`welcomeShown` 记录是否已发送，改为 `false` 可在下次进入 Hypixel 时再次发送。`/skyzh`（或 `/skyblockzh`）与 Mod Menu 共用设置页面，欢迎语与 GitHub 链接仍在通用分类顶部。
启动清空在 Fabric 客户端初始化回调中执行一次，进入主界面前已经完成；与 `/skyzh clear` 共用
`TextCapture.clear()`，清理内存、队列和六个采集分类里的 JSON，保留其他文件，失败写日志而不阻止启动。

原文键是原版 `KeyMapping`。`OptionsMixin` 在 `Options.load` 开头追加注册（重复加载不重复追加），
因此第一次读取 `options.txt` 时就能恢复自定义键位；保存、冲突显示、重置及 NONE 都由原版处理，无需 Fabric API。
默认 X **按一次切换原文，再按一次恢复**；保留旧类名 `HoldOriginal` 和键位 ID 以兼容已保存的绑定。
键盘及扫描码只响应按下事件，忽略重复/松开；鼠标绑定在 tick 检查物理按下边沿。
聊天、书本/告示牌、文本框（包括嵌套焦点）、改键界面与失焦时不触发，但已切换的原文状态保留，因此可先切换再打开聊天查看历史。
切换世界、暂时缺少空岛计分板或离开空岛不清除原文模式；关闭总开关或解绑才清除临时状态，不写配置、不改变采集开关。
有效按键切换时播放方块分类的 `ui.button.click`（音量参数 100、音高 2），并提示已关闭/开启翻译；自动清除状态不播放。
符合提示条件的物品 Lore 按当前模式显示“按下 X 键显示原文/翻译”，X 使用实际绑定键名，颜色不变。

聊天绘制前检查实际翻译状态，包括总开关变化；只重建显示行，不改 `allMessages`，并保留有界的滚动位置。
`ChatDisplayCache` 按消息、字体、宽度、语料与玩法名选项有界缓存译文组件；默认聊天每次排版仍执行其他 Mod 的拆行链路，
以保留其逐行渲染器登记。高档独立视图继续缓存折行结果。切换原文不再清空译文缓存。
检测到 Better Hypixel Chat 时，只在原版聊天显示队列调用内为当前消息提供译文视觉序列；过滤、搜索、历史及显示行父对象仍使用原文。
Compacting、Enhanced Chat、Stfu 的灰色重复计数仅在正文与数据包快照完整一致时单独保留，不把服务器原句中的括号当作计数删除。
包快照随原版消息对象保存，不另建历史列表；不注入第三方类。
字体/布局重排、历史清空和组件内容变化会失效相应缓存。首次显示另一种语言或原文期间收到的新消息仍需处理，
这不是低配置实机帧率保证；原先松开热键时重新翻译整份聊天和清空 Tooltip 缓存的重复开销已移除。

```bash
./gradlew checkClientSettings  # 所有目标均检查配置兼容、原版键位、非 Hypixel 边界
```

需要游戏内实测的部分：在按键绑定界面改键、解绑、重启确认保留；打开物品菜单按两次比较原文、切换后打开聊天查看历史；
验证新增按钮左右布局；开启自动清空后重启到主界面确认已删、同一轮断线重连确认未删。

### 显示优先级

设置页分为「常规设置」和「开发者设置」。常规设置第三行的显示优先级按「默认 → 高 → 强制」循环，
无需重启；右侧「翻译物品名」控制真实物品名称及各处明确标记的物品引用，修改后刷新 Tooltip 与已有聊天显示，无需重启。

- `default`：使用显示阶段翻译及检测到的聊天适配，不检测辅助计分板、不启用增强来源补译或独立显示视图。
- `high`：承接原强制档的文字/字体保护、原始物品名称与 Lore 重建、服务器聊天显示视图。
  检测 CustomScoreboard、SkyHanni、NoammAddons 的只读公开状态；对方启用或接口不兼容时让出计分板，
  仅补译可确认的服务器完整行，保留其颜色、图标、缩进与交互。对方临时隐藏面板时也不补画。
  服务器行最多额外保留 20 tick，覆盖缓存显示延迟；无自定义面板时在最终层绘制服务器计分板。
- `force`：包含高档的显示保护，并在 `GameRenderer.extract` 的作用域内接管计分板。
  原版 `GuiRenderState.findAppropriateNode` 提交入口通过最多 64 层调用来源识别上述三个已核对的计分板渲染器，
  拒绝其文字、背景、图片和物品提交，再绘制服务器原始计分板的译文；不是按坐标覆盖，也不屏蔽同一 Mod 的其他 HUD。
  原版 Tooltip 排队和 Widget 点击入口同时拦截被替代面板的相关操作。仅在只读探测确认面板启用或接口状态未知时
  扫描绘制调用栈；未安装或所有面板关闭时跳过。
  帧结束或异常均解除拦截，切回高档恢复对方面板，不修改第三方设置、数据或类。

高档与强制档重建物品提示时，额外的 Mod 提示或 Tooltip 图片可能不再显示。来源只认服务器消息及当前 HUD，
不把任意第三方文案拿来遍历语料；前缀预筛仅跳过不可能匹配的文本，最终仍要求完整来源匹配。
替代计分板背景遵循原版文字背景不透明度。未知渲染器、超出已核对调用链的异步绘制及直接 GPU 绘制不保证被拦截。

聊天在已确认连接 Hypixel 且总开关开启时保存最多 100 条、共 128 Ki 字符的显示用历史；服务器系统消息在数据包分发时
保存原文快照，客户端提示与签名玩家消息另行保留且不翻译。高档与强制档只在原版聊天绘制、点击命中和滚动期间临时
使用这一显示视图，结束或异常时还原原版显示队列与滚动状态，不写 `allMessages`、不重发聊天事件。
因此重复计数、上游翻译或异步替换显示行不会改变原文来源，被辅助 Mod 过滤的服务器消息可能重新出现。
点击、悬浮、折行和淡出继续使用原版逻辑；独立滚动锚点随新消息和重排调整。原文键只切换此视图的语言。
历史与原版聊天记录同寿命：换世界时随原版的 `storeState` / `restoreState` 保留，断线、关闭总开关及清空聊天才清理，字体重载只清布局缓存。

所有档位遵守 Hypixel 空岛边界、总开关和原文热键。`PriorityText` 的来源记录有容量上限，离开空岛、换世界、关闭总开关、切换档位或高档的自定义计分板启用状态变化时清空；默认档不收集增强来源。
独立聊天历史在默认档期间也继续有界收集，便于切到高档或强制档时保留近期消息。
原文模式下继续保留来源，恢复译文无需等服务器重发。配置变化会清空译文保护记录。
强制档不是 Fabric 的全局排他锁：完全替代原版聊天绘制的渲染器、在包分发前删除的数据及更晚提交的图层仍可能影响显示。
运行日志按状态变化限流报告身份、侧边栏、语料加载、总开关和原文模式等门控原因，不记录聊天正文或玩家身份。
`checkDisplayPriority` 验证来源限制、颜色策略、Unicode、聊天快照、滚动锚点、缓存上限及隔离；多 Mod 的最终视觉效果仍需实机验证。

### 在哪替换、在哪不替换

这个词会出现在没人翻过的英文句子里，所以它恰好是全 Mod 唯一一处可能造出"本 Mod 存在就是为了消灭的那种东西"
的地方：一整行英文里孤零零一个中文词。因此在语料**没有**覆盖的行上，只有当 `SkyBlock` 是这一行里
唯一的英文词时才替换（判据见 `SkyBlockName.isTheOnlyEnglishWord`，数字和符号不算英文词）。

| 行 | 结果 |
|---|---|
| `SKYBLOCK`（侧边栏标题） | 空岛生存 |
| `SkyBlock Level 42` | 不动——`Level` 还是英文 |
| `You unlocked SkyBlock XP!` | 不动 |
| `SKYBLOCK CO-OP` | 不动——`CO-OP` 是另一个英文词 |

语料**已经**覆盖的行上，替换是在译文之上跑的，所以一条译文里保留了这个词的记录——`"SkyBlock 菜单"`——
开关打开时显示「空岛菜单」，关闭时显示 `SkyBlock 菜单`。想让某一行早点翻出来，正规做法就是这个：
写记录、译文里把词留着，开关照旧管得住它。

### 玩法名的空格与简称

译文里把 `SkyBlock` 前后留空格是正确的中文排版（拉丁词与汉字之间该有空隙），但换成中文之后这些空格
就成了汉字之间的空格，中文里并不存在，会显示成「你的 空岛生存 等级」这种断开的样子。所以替换时会重新
判断：空格两侧都变成汉字就删掉，一侧仍是数字或字母就保留（`+150 空岛经验` 里那个空格是对的）。

同时按中文习惯在复合词里用简称：后面紧跟汉字说明构成了「空岛菜单」这类偏正结构，用「空岛」；
独立出现（后面是标点、字母、行尾）用全称「空岛生存」。少数助词方位词不算复合，
`在 SkyBlock 中` 仍是「在空岛生存中」。译名、简称和这张排除表都在
`_shared/SkyBlock_Name.json`，改文件即可，不用动代码；把 `short` 设成和 `full` 一样就等于关掉简称。

### 属性图标是服务器字体画的

SkyBlock 以前把属性图标当普通字符发（`❤ Health`、`☘ Mining Fortune`、`⸕` 是 Amber），现在改成了
私用区码点，由服务器资源包里的字体渲染。语料的两个来源对这件事的说法不一致：wiki 记的是老符号，
NEU-REPO 里是抓取当天服务器发的那种。

写法不同的两边永远匹配不上，而且**什么征兆都没有**——不报错、数据也不算坏，就是那句话一直是英文。
所以匹配前会把两边折算成同一种写法，画中文时再把图标换回**服务器这一行实际发的那个字符**：
屏幕上的图标还是 SkyBlock 自己的，只有字变成了中文。

### 藏在词中间的标记

计分板的每一行必须是互不相同的字符串，Hypixel 的办法是往文字里塞一个 `§` 加一个字母——
`Dwarven M§qines`、`W§qind Compass`——每一行塞的位置还不一样。`q` 不是任何一种颜色，
而这正是重点：游戏的渲染器碰到 `§` 就把它和后面那个字符整对吃掉，认不认得都一样，
于是这个标记在数据里存在、在屏幕上不存在。

Minecraft 自带的 `ChatFormatting.stripFormatting` **不是**这么做的——它只删有名字的颜色码，
剩下的原样留着——用它读文本的 Mod，读到的就是两个玩家看不见的字符。
这点差别值得单写一段，是因为它坏掉的东西有多少：计分板那几行永远匹配不上记录、一直是英文，
采集下来的每一行都被归到一个叫 `Dwarven M§qines` 的地方去。
现在本 Mod 里所有把文本摊平的地方都走同一个读法 `StyledText.plainOf`，也就是渲染器的读法。

## 翻译语料

语料在 `original_text/`，按玩法分类 × 渲染位置分目录，规范见 `original_text/README.md`。
Mod 读取打包时删除译者说明字段后的 JSON，运行时字段保持一致——屏幕上一行不对，就能直接查到是哪个文件的
哪个 `id`。`zh` 为空表示尚未翻译，该行保持英文，不会被抹掉。

动态模板按必含字面片段建立候选索引，再按字面量长度、原注册顺序执行完整正则和占位符校验。
相同定义共享编译结构，各引用仍保留自己的 ID 与来源；不按玩家所在岛屿删减模板。
`StyledText` 保存连续样式段，子范围共享不可变样式存储；Lore 在一次规划内复用行快照和起点查询，
继续选择最长完整匹配，保留 12 行、2048 字符和空行边界。
原版每帧重建的头顶文字、侧边栏、Tab 行与 Tooltip 若只含字面文本，按逐节点文本、样式与子节点数命中已记录的结构，
不再重复展平；任何原地修改都会落空并回到完整键。首次语料在后台线程加载，完成前 SkyBlock 判定保持关闭；
游戏中的重载继续使用上一份有效索引，不关闭门控。

### 完整翻译包与热重载

`original_text/_data/` 中的 `item-names.json`、`areas.json`、`preserved-text.json` 与翻译记录一起维护、
精简和打包。它们分别保存物品身份目录、区域分类及专名／档案身份参考；Mod 自身的语言资源仍由 Minecraft 加载。
内置语料和外置包都复用 `TranslationLoader.compile`。`CorpusData` 随索引发布，采集工作队列记录入队时的索引，后台处理固定该代数据。

运行 `python tools/export_translations.py` 可生成并校验 `build/translations/translations.zip`，也可直接使用
`./gradlew packTranslations checkTranslationPack`。ZIP 根目录包含 `manifest.json` 和保留相对路径的 `original_text/`；
导出复用 `minifyCorpus`，临时文件写完后替换正式文件。脚本支持 `--output <目标文件路径>`，校验成功后才复制到目标位置。
需要 JDK 25 和项目 Gradle 环境。玩家将 ZIP 放入当前 Minecraft 实例的 `skyzh-translations/`，无需解压；
目录由 Mod 创建，通过 `FabricLoader.getGameDir()` 定位，开启版本隔离时不是启动器程序所在目录。
启动或 `/skyzh reload`、`/skyblockzh reload` 时读取固定的 `translations.zip`，读取后关闭，不持续占用文件。

手动包 `skyzh-translations/translations.zip` 始终优先；没有可用手动包时，自动包 `skyzh-updates/translations.zip` 只有在 API 兼容、生成时间比内置包新且内容摘要不同时才优先，否则使用内置语料。
来源不存在或 JSON、必要表、引用、数量、摘要、API／格式检查或编译失败时，尝试其他可用来源；全部失败则保留当前索引。
内置语料编译成功后清理已被替代的自动包，删除失败只记日志；内置加载失败则保留并使用可用自动包。
每个包整体替换语料，不逐条混合，因此不会复活已删除模板。移走全部外置 ZIP 后重载可恢复内置版本。
并发重载请求会被拒绝，新索引在客户端线程发布，刷新显示缓存与采集去重索引，保留原文模式、设置及聊天历史。

`gradle.properties` 仅声明一个固定的 `translation_api`，同时写入 Mod 资源和翻译包清单。包 API 必须与引擎声明完全相等，
较低或较高的值均不接受，不再根据 Mod 版本判断兼容性。新语料要求或引擎行为破坏兼容性时自增 API，纯措辞修改或兼容的优化不变。
`format_version` 独立声明 ZIP／清单的结构版本，当前仍为 1。API 4 移除了必填的 Mod 版本范围字段，API 3 的旧包需重新导出后供新引擎使用。
`revision` 为导出时 HEAD，`source_dirty` 表示语料／构建规则／版本属性存在未提交修改；`build_at_utc8` 为带 `+08:00` 的生成时间。
这些溯源字段不用于推断兼容性。`content_sha256` 按相对路径排序，对每个文件依次写入“UTF-8 路径、NUL、原始 JSON 字节、NUL”计算，
不包含清单自身，单纯重新打包不会改变内容摘要。

`checkTranslationPack` 验证真实导出内容、辅助数据、API 严格匹配与独立包格式校验、失败回退、缓存更新及后台数据代际，接入所有目标的 `check` / `dist`。
实机仍需确认打开的菜单、聊天滚动、原文模式及三个显示优先级下的重载表现。

### GitHub 自动更新

`.github/workflows/translations.yml` 每次 push 触发，主分支运行 `tools/publish_updates.py`，相对上次成功发布的来源提交检查完整打包输入；首次发布和手动 `workflow_dispatch` 强制打包。复用 Python 导出与 Gradle 校验，ZIP 明确使用 DEFLATE 等级 9。
脚本以 `--prepare` 生成 `build/pages`，由 Pages 整站部署至 `https://skyblock.xbdqaq.com/`。`skyzh-updates/update.json` 提供翻译与测试版清单，`release.json` 提供正式版清单；客户端检查与下载均使用该域名。部署保留前两版翻译包及上一组测试版、正式版 JAR，旧 Pages 地址在发布时迁移。`--publish` 校验当前下载文件后记录仓库清单，构建期间输入变动则不覆盖。仓库清单供旧客户端读取，翻译包和测试版地址指向 `legacy-updates` 预发布附件；新域名清单保持站点地址，原始状态另存于 `pages_state` 供后续部署保留文件。兼容附件按摘要命名，不覆盖旧链接，也不影响最新正式 Release。需配置 Pages 自定义域名及 `contents: write`、`pages: write`、`id-token: write` 权限。

正式版发布：运行 `./gradlew dist`，将三个正式 JAR 上传至版本号对应的 Release 后发布，保留 GitHub 下载入口供旧客户端自动升级。`published`、`edited`、`released` 事件转发为主分支部署任务，从最新正式 Release 校验 Mod ID、版本、渠道、大小和 SHA-256 后镜像附件；失败可手动运行工作流重试。普通推送只生成翻译包与测试版，并补同步有变化的正式 Release。

客户端在 `HypixelServer.isSkyBlock()` 且首次语料加载已结束时启用后台更新，不在启动初始化或单纯进入服务器时联网。自动检查、主动检查及重试按钮复用一个后台任务和忙状态；同时检查两项时按 Mod、翻译包顺序执行，各项保留独立冷却，Mod 检查失败不阻止随后检查翻译。
翻译清单从自定义域名直接读取，包含 `update_format: 1`、包级清单字段、`download_url`、`zip_size` 和 `zip_sha256`；API 必须完全相等，日期较新且内容摘要不同时才下载。比较基准与加载选择共用时间和摘要规则：只有比内置包新的可用自动包才作基准，否则使用内置元数据，即使旧自动包尚未删除也不会影响检查；内置资源 `skyzh-builtin-translations.json` 与 ZIP 清单由同一构建任务生成。手动包不参与自动更新的版本比较。

临时下载支持 Range 续传，以固定 URL、大小和 SHA-256 标识同一文件；不支持续传时重新下载，不拼接不同响应。连接及响应有超时，流读取以 60 秒无数据为超时，允许持续有进度的慢速下载。完成后核对归档摘要和包内清单、校验语料并编译，持有现有重载锁后才替换正式自动包并切换索引；手动包仍优先。失败保留当前正式包及运行索引。

`config/skyzh-updates.json` 分别持久化 Mod 和翻译的检查时间、结果及详情。一般成功、无更新和失败均一小时后允许再检查；API 不兼容仅让翻译通道等待七天。当前游戏会话到期且仍在空岛时重试；离线则下次进入空岛时重试，不限制次数。Mod 版本／本地 API 改变会使相应旧冷却失效。更新目录准备失败的冷却也先写入配置目录。首次语料加载失败不阻止后续下载有效包恢复翻译。聊天只显示简明提示，详细错误写日志。错误提示的重试按钮跳过等待时间，复用原下载、校验与安装流程及并发锁；初始化错误可重新准备目录并检查两类更新。只有确有新 Mod、存在较新的翻译且 API 不兼容时，才显示新版 Mod 下载按钮；缺少当前 Minecraft 附件时静默记录。手动包覆盖提示带不可撤销的卸载按钮，在正常重载锁中仅删除 `skyzh-translations/translations.zip` 并按原优先级加载自动包或内置语料。按钮通过有容量上限的本地随机令牌调用隐藏命令，所有别名均在客户端拦截；只有括号按钮带点击和悬浮事件；重试请求受理后旧按钮失效，再次失败会生成新按钮，未受理时仍可点击；卸载完成后按钮失效，失败时仍可重试。

测试版渠道：同一个 Actions 在打包输入（含 `src/`、各 `fabric-26.x/`）变化时以 `-Pskyzh.channel=beta` 构建三个目标的 JAR，版本为 `<版本>+mc26.x.beta.<提交数>`，放到 Pages 的 `skyzh-updates/mod/<SHA-256>/`，并在 `update.json` 的 `mod_beta.assets` 中按目标记录版本、大小与摘要；部署时保留上一组测试版文件。所有 JAR 内的 `skyzh-build.properties` 记录渠道与提交数：测试版按提交数比较（同基础版本下提交数更大才更新），切回正式版渠道时，同版本的正式版会替换测试版。
Mod 通道从站点 `release.json` 选择当前 Minecraft 目标的正式 JAR，要求镜像时验证的 SHA-256，并检查 `fabric.mod.json` 的 Mod ID、版本及 Minecraft、Fabric Loader、Java 依赖。校验通过后保存在 `skyzh-updates/mod-update.jar`。独立的 JDK 安装程序从内嵌 `skyzh-updater.jar` 启动，确认准备完成才提示用户；等待游戏 PID 及启动时间对应的进程退出后，再校验下载文件、备份当前 JAR 并替换原文件名，避免 `mods/` 同时存在两个版本。手动替换视为手动更新，旧安装记录不阻止后续自动更新；等待退出期间手动放入的 JAR 也允许覆盖，替换前备份实际文件。下载文件仍须通过摘要校验；替换失败记录到 `mod-install.properties` 与 `installer.log`，后续允许继续尝试。开发环境、嵌套 Mod 及当前实例 `mods/` 之外的安装不自动替换。个别启动器结束整个进程树或立即重新占用 JAR 时，可能需要再次启动后重试。

`checkUpdates` 使用本地 HTTP 服务验证中断续传、取消、超时、校验失败、冷却持久化、安装优先级、按钮文字／样式／本地动作、立即重试与卸载重载，以及真实子 JVM 退出后的 JAR 替换；`checkUpdatePublisher` 验证 Pages 文件暂存、前两版保留、下载校验与清单发布顺序，不写 GitHub。完整客户端与启动器组合仍需实机验证。

`./gradlew checkPerformance` 将索引结果与原逐条扫描算法对照，并验证样式、缓存碰撞、结构命中和采集逐出恢复。
`./gradlew benchmarkPerformance` 输出离线耗时及分配量；不代表实机帧率。测试源码、平台适配样例、
JSON 样本和 Python 检查统一位于 `tests/`，不打入分发 jar。

改完语料跑一次回归测试，不用进游戏：

```bash
./gradlew checkTranslations
```

它用真实语料跑真实匹配引擎，逐条核对颜色重建、占位符搬运、缩进保留、类目隔离等结果。
唯一覆盖不到的是需要字体的部分（折行与居中要量像素），那些只能在游戏内验证。

另一半问题不是「这条记录对不对」，而是「实际玩一局，屏幕上出现过哪些语料压根没收录的句子」。
把同一个引擎对着客户端日志跑一遍就有答案：

```bash
./gradlew auditLog                        # 读 logs/ 下所有日志
./gradlew auditLog -Plog=logs/latest.log  # 只读一个
```

Minecraft 本来就会把收到的每条聊天消息写进 `logs/`，这个任务只是读那个已经存在的文件。
输出是「没有任何记录应答的行」，按出现次数排序。

## 运行时采集（默认关闭）

日志只有聊天。**NPC 打开的那个界面里每一格物品叫什么、Lore 写了什么**，日志里没有，wiki 的
`/UI` 子页覆盖不全，NEU-REPO 只有物品本体不含菜单——这块内容只存在于「有人正在玩的那块屏幕上」。
`captureUntranslated` 就是为这一块存在的：打开之后，语料答不上来的服务器原文会被写到
游戏目录下的 `skyzh-capture/`。**它不改变游戏里显示的任何东西**，只读不写。

### 为什么这次不会把别的 Mod 的文字采进去

上一次做这个功能就是栽在这里，而且没法补救：文本一旦画到屏幕上就只是文本，SkyHanni 画的那一行
和服务器发的那一行长得一模一样，事后再怎么过滤都分不出来。**错的是挂钩子的位置，不是过滤规则。**

这次每一个采集点都挂在**数据包处理函数**上，或者挂在只有数据包才写得进去的状态上：

| 采什么 | 挂在哪 | 为什么进不来别的 Mod 的东西 |
|---|---|---|
| 聊天（系统 / NPC） | `ClientPacketListener#handleSystemChat` HEAD | 比 Fabric 的聊天事件、比 SkyHanni / SkyBlocker 都早。Mod 自己发的消息走 `ChatComponent#addMessage`，**根本不经过这个方法** |
| 界面标题 | `handleOpenScreen` HEAD | 服务器包里的 `title` 字段 |
| 物品名 + Lore | `handleContainerContent` / `handleContainerSetSlot` HEAD | 读 `ItemStack` 的 `CUSTOM_NAME` / `LORE` 组件，**不是** `getTooltipLines()`——后者正是所有 Mod 往 Lore 里加东西的地方 |
| 头顶文字 | `handleSetEntityData` TAIL + 每 10 tick 复查包里见过的实体 | 名字、可见状态或隐形位更新时登记实体；有界 ID 集合绑定所属 `ClientLevel`，换世界清空。采集隐形盔甲架的可见名字及非玩家活体实体的自定义名字，不遍历其他 Mod 创建的实体。NPC 专名、宠物名字和未知动态血条均可留下证据，只有实际已有译文的通名才视为覆盖 |
| 计分板 | 每 10 tick 读一次 `Scoreboard` 对象 | 和原版渲染读的是同一份服务器状态。附带好处：**SkyHanni 的自定义计分板把侧边栏整个接管之后，这里照样拿得到 Hypixel 的原始行** |
| Tab 列表 | `handleTabListCustomisation`（页眉页脚）+ 每 10 tick 读一次玩家条目 | 同上 |
| BossBar | `BossHealthOverlay#update` TAIL | 那张 map 只有服务器包写得进去 |
| 动作栏 / 标题副标题 | `setActionBarText` / `setTitleText` / `setSubtitleText` HEAD | 同上 |

书本与告示牌分别使用 `Surface.BOOK` / `Surface.SIGN`，读取 `Book/` / `Sign/` 语料。书本只在
`BookViewScreen.visitText` 读取当前页时生成显示译文，原版折行缓存同时用于绘制、悬浮与点击命中；
总开关、原文状态或语料代际变化时刷新，不修改书本组件，也不翻译编辑器内容。完整页/面模板优先，
未命中时按显式换行逐行查找，保留空行。书页内有几何依据的居中空格按 114px 页宽与实时字体重算，
短缩进保持原位。告示牌在 `AbstractSignRenderer.submitSignText` 准备文字时翻译四行显示副本，
沿用原版按译文宽度逐行居中、染料与发光绘制；普通/悬挂、正/背面及过滤文本均沿用原版选择。
不会把译文写入 `SignText` 或其原文渲染缓存；外置模板输出不是四行时回退原文。书本按钮继承实时
点击事件与样式，文字悬浮说明只查询 BOOK 语料。`checkDocuments` 回放采集样本并检查交互、颜色、布局和类目隔离。

采集入口在数据包自身 `handle(ClientGamePacketListener)` 的最高优先级
HEAD，提交采集时复用 `TextCapture.ready()` 的开关与服务器门控，以及原有后台队列、地点等待、去重和清空。
书本从容器全量/槽位、玩家背包和光标物品包的原始 `WRITABLE_BOOK_CONTENT` / `WRITTEN_BOOK_CONTENT`
一次冻结所有页（选 `Filterable.raw`），不等打开或翻页，因而未翻到的后页也能采全；不读取书本编辑器或客户端
背包的后续状态。客户端线程在门控前或采集关闭时也仅在内存保留候选（最多 64 份、页字符合计 1 Mi），
待身份、空岛门控通过且采集开启后提交，所以初始包早到、后来手动打开书与笔也无需重发。此策略也会预采
尚未打开的服务器书本。候选按原始快照去重，超限逐出最旧候选，单份超过字符上限不暂存；换连接、换世界、
断线及清空采集时丢弃，不读取本地编辑内容补齐。告示牌仍只处理采集门控已经通过时收到的包。
告示牌从区块初始方块实体 NBT 与方块实体更新包直接用该版本的 SignText codec 解码，限定普通/悬挂告示牌，
不读取世界里的最终 SignBlockEntity 或渲染缓存。26.1、26.2、26.3 的 codec、实体类型常量及区块遍历差异
由 `platform/ServerSignData` 适配；26.2 单独选择 `src/sign26_2/`，26.3 仍复用其 GUI 源码。

输出分别在 `Book/Books.json` 和 `Sign/Signs.json`。书页按整页保存换行、颜色、原始空格，
`_capture.book_contexts` 保存标题、作者、包槽位、总页数、从 1 开始的目标页码与完整目标页；空页保留在原始
快照及页码中。告示牌按一面整体保存，`_capture.sign_contexts` 包含维度、坐标、普通/悬挂类型、正背面、
染料、发光及原始四行（含空行和符号）。精确 RGB 等无法无损写成旧颜色码时额外输出 `style_runs`。
每条记录最多保留三个具体上下文，达到上限时标注 `server_contexts_limited`。这两种采集面按各自
BOOK/SIGN 语料诊断已覆盖文本及颜色、混杂和数值问题，不查询 MISC；未覆盖的纯符号仍会记录，
全空白页/面只作为上下文或页码保留。
`checkCapture` 验证包组件/NBT 快照的来源隔离、后页完整性、空行、原始空格、正背面及颜色，
以及书本候选在门控开启后提交、关闭时不落盘、连接/世界生命周期清理和缓存上限。

注意这里**故意没有**按名字过滤：`[Bazaar]`、`[Sacks]` 是 Hypixel 自己的前缀，做一张「Mod 名黑名单」
只会把真的 SkyBlock 文本误杀掉，去挡一个本来就进不来的东西。

再加两道闸：当前这条连接必须自报为 Hypixel（官方的 `hypixel:hello`，或写着 Hypixel 的
`minecraft:brand`），且侧边栏 objective 的内部名必须是
`SBScoreboard`，缺一都不采；连接地址不参与判断。每个采集入口即时检查当前连接，
切服后不沿用上一 tick 的放行状态；即使中途关闭采集，断线或离开 SkyBlock 时仍会清理会话状态，
但不会删除磁盘文件。

### 唯一一处会向 Hypixel 发包的东西

采集**打开**时，而且只有装了 [`hypixel-mod-api`][modapi] 这个 Mod 时，SkyZH 会订阅 Hypixel
自己的位置事件——一个注册包，由那个 Mod 的管道发出去，内容就是"我要这个事件"。
换来的是玩家一落地服务器就直接告诉你人在哪个岛，也就是把"这段文本该归哪个玩法"这件事
从"读一块画给人看的侧边栏"换成"问服务器"。那个库只在编译期引用、不打进 jar；
没装那个 Mod 这段代码根本不加载，另外两个读法照旧。

采集**关闭**时——也就是所有普通玩家——什么都不订阅，也不向 Hypixel 发包。
这与 `updateCheck` 独立：后者仅在总开关和自动更新开启、且已进入空岛生存时请求更新站点，下载 Mod 与翻译包，不上传游戏数据，也不向 Hypixel 发送更新相关数据。
正式 Mod 更新比较站点 `release.json` 与 Fabric 版本，忽略 `+mc26.x` 构建元数据；只推代码或标签不构成正式 Mod 发布。翻译更新由 Actions 部署到自定义域名并更新仓库状态清单。
翻译那一半仍然是标题上写的那句话：装了 SkyZH 的客户端，在 Hypixel 和别的 Mod 眼里，
就是一个跑英文的客户端。

[modapi]: https://github.com/HypixelDev/ModAPI

### 采到的东西长什么样

输出分六类，各自再按 `original_text/` 的结构分目录（玩法 / 渲染面 / 名字）：

```
skyzh-capture/
├── untranslated/          没有任何记录应答的行
│   ├── Mining/NPC_Message/Fragilis.json
│   ├── Mining/GUI_Item/Commissions.json        ← 这个菜单里所有格子的名字 + Lore
│   ├── Mining/Hologram/Holograms.json
│   └── _Unknown_Gameplay/ScoreBoard/Sidebar.json
├── mixed/                 有记录应答了，但屏幕上仍然中英混杂
│   └── Mining/ChatMessage/Server_Messages.json
├── colour/                有记录应答了、每个字都是中文，颜色却被压平了
│   └── Mining/ScoreBoard/Sidebar.json
├── layout/                聊天对齐策略冲突、偏移或译文超宽
├── incomplete/            已译 Lore 后残留疑似英语续行
└── value/                 数值丢失、未输出占位符或无源占位符
```

第三堆是别的办法很难发现的那一类。游戏里一行文字中途换色，语料里却记成了一整行，
译文就会被整段刷成最前面那个颜色——金色的 `5` 旁边一个白色的 `(+`，蓝色的数值旁边一个白色的雪花。
启动日志只能说「这条记录压平了颜色」，永远说不出**颜色是在哪儿换的**；采集文件说得出来，
它会按服务器实际发的颜色边界把 `segments` 数组切好写进去，指名道姓地告诉你抄进哪条记录。

这里只认**画得出来**的那部分样式。Hypixel 会为了挂一个悬浮提示而把一行切开，切法和换颜色时一样——
收纳袋那条消息里 `" items"` 和后面的 `"."` 是同一种黄色的两段，区别只在前一段带着「Added items:」的悬浮框——
按整个 `Style` 相等去判断，就会把一条 `segments` 本来就正确的记录推进这一堆，
还建议你在一个两边颜色相同的位置再切一刀。所以比较只看颜色、字体和五个格式开关。

玩法从"采集当时人在哪"推断，对照表在 `original_text/_data/areas.json`，
认不出来就落进 `_Unknown_Gameplay`，补一条到那个文件即可，不用改代码。

"人在哪"有三个读法，按这个顺序问：侧边栏 `⏣` 那一行 → Hypixel Mod API（装了 `hypixel-mod-api` 才有）
→ Tab 列表的 `Area:` 那一行。顺序不是随手定的——侧边栏给的是岛上的小地名
（Fairy Grotto 而不是 Crystal Hollows），最细，但它是由队伍的前缀和后缀拼出来的，
每次传送之后也是最后才拼好的一块，而那正好是另外两个读法已经能答话的时候。
在两个读法都还没答话的那一两秒里采到的文本会被**扣住**，最多等八秒，
等地点出来了再按那个地点落盘——那本来就是它来自的地点。
只有侧边栏自始至终不答话，才会有东西真的落进 `_Unknown_Gameplay`；
真到那一步，日志里会把侧边栏和 Tab 列表原样打出来（看不见的字符写成 `\uXXXX`），
否则"一堆未知玩法"和"表里少一条"从输出上根本分不出来。
来源认不出来落 `_Unknown_Surface`，名字认不出来落 `_Unknown_Name`。

每条记录就是 `original_text/` 的记录格式，颜色码原样保留、变色的行自动切好 `segments`、
`zh` 留空。搬进语料只需要删掉 `_capture` 块、核对占位符、填 `zh`。

### 采到东西会在聊天里说一声

由「采集文本提示」子开关控制，默认打开。关闭后仍写采集文件，但会丢弃待发报告，重开不会补发
静默期间的报告。采集到的会**按输出文件合并**，最后一条进来 1 秒后发一条：

```
§b[SkyZH]§f 采集 43 条 · §7Mining / GUI_Item / §eCommissions§8  在 Dwarven Mines
         §7未翻译 41、中英混杂 2  §9[打开未翻译]  §9[打开中英混杂]
```

末尾那个"在 XXX"是采集当时侧边栏报的**地点**,只有它和玩法目录不是一回事时才写。
`Hub_General` 是个目录不是个地方——大厅、私人岛屿、博物馆的通用文本都落在那里,
只报目录名的话,在自己岛上开的菜单看起来就像是在大厅开的。

为什么要合并:一个 SkyBlock 菜单服务器一口气发 54 格物品、每格十几行 Lore,逐条发会瞬间刷四十行,
把聊天框(默认只显示 10 行)里别的东西全顶掉。聊天类文本本来就是一条一条进来的,
合并对它没有影响——一条消息安静下来的那一刻就发了。文件名可以点,用系统默认程序打开那个 JSON,
鼠标悬停能看到完整路径。持续采集超过 5 秒也会强制发一条,不会一直攒着。

这条消息是**客户端消息**(`addClientSystemMessage`),不是伪装成服务器发的。它不经过数据包,
所以采集器看不见自己;但 Minecraft 会把它写进 `logs/latest.log`,所以 `auditLog` 那边按
`[SkyZH]` 前缀跳过了它,不会把自己的提示当成未翻译文本报出来。

### 它替你判断的几件事

**同一句话只有数字/名字不同的，会归并成一个模板。** 这是上次搁置的第二条理由（分不清哪部分是
可变数值），答案是：一次观测确实分不出来，多次可以。**只有同一位置被观察到 ≥2 种取值才敢当成占位符**，
而且见过的取值全部列在 `_capture.observed` 里给人复核；只见过一种取值的位置原样留着不猜。
切口还不许落在数字中间（`x23`/`x24` 的模板是 `x%s` 而不是 `x2%s`），也不许落在单词中间
（`Force`/`Axe` 不会被切成 `Forc`/`Ax`）；占位符比句子本身的词还多时直接拒绝归并，
免得把「你 XX 了 YY」这种语法当成一句话。

**同一行在别的菜单里出现过就不再记一份。** SkyBlock 每个菜单都带着同一套返回按钮、同一段稀有度
说明，指南类菜单每一页顶上还是同一段介绍；而且**容器内容包尾部那 36 格是玩家自己的背包**，
每开一个菜单都跟着发一遍。按菜单各记一份的结果是：一次会话 9758 条记录里，有 5208 条是隔壁文件
里那条记录的副本。现在背包那 36 格落进 `_Inventory`，跨菜单重复的行只留第一次见到的那一份，
其余出现过的菜单记在 `_capture.also_seen` 里——那一行有 `also_seen`，就正好说明它该按 §5.6
抽进 `_shared/`。同一玩法内才去重，把 Foraging 的行记进 Mining 的文件夹是没人事后能发现的污染。

**别人的名字进不来。** Hypixel 在等级和称号之间画一个公会图标(`⸕`、`ᛝ`——有些还是字母)，
名字后面再挂 AFK / 组队符号。以前这几个符号让"这一行只是个玩家名"的判断失效，
于是一次会话把三条陌生人的聊天和五十个陌生人的用户名写进了采集文件。

**已经是中文的行不采。** Hypixel 自己有一部分中文文案（大厅传送、进服公告），那不是本 Mod 的活。

**「差一点就匹配上」会被指名道姓。** 一行没被翻译，但语料里**确实有**这句话、只差在不可见字符上
（私用区图标、不间断空格、全角标点）——这是本项目最贵的一类 bug，因为看屏幕、看日志、看数据文件
都看不出来。现在这种情况会在记录里写一条 `near_miss`，指出是哪个文件的哪条记录，
并把两边的文本都用 `\uXXXX` 转义打出来。

### 对齐、跨行和数值诊断

`ChatLayout` 在渲染与服务器聊天包采集时使用相同的布局计算。它用客户端实际字体测量原文左边距、
正文及译文宽度，以服务器默认 320px 和当前聊天宽度为已知参考。短缩进保持左侧；足够的填充还要符合
中心或右边缘才能确认对齐。共用模板或未声明布局的文本会据此修正位置；显式居中/左/右策略优先，
与几何推断冲突时只报告疑点。说话人前缀参与整行测量，其后的旧填充不重复保留。
诊断保存策略和像素数据。未找到可靠锚点的布局保留原样；这不是截图识别，也不能判定其他 Mod 自绘界面的设计意图。

`LoreTranslation` 为 Tooltip 和原始物品 Lore 采集生成同一份处理计划。容器包在主线程只保存不可变的物品名、完整 Lore、菜单、槽位与区域快照；整句匹配、颜色及数值诊断在现有采集后台线程完成，避免打开集市时同步分析整箱物品。后台仍保留重复次数、原始上下文及清空代际，不读取后来变化的 ItemStack。
`incomplete` 报告保留疑似残留的
有序原文与输出，便于区分漏译半句和重复英语尾行；它只报告疑点，不自动吞掉未知行。判定只看玩家能读到的
字符（`§k` 乱码装饰不算）：尾行以小写单词开头即算续行；以大写开头时，只有首行本身像句子（含小写单词、
不含冒号、不以句末标点收尾）且尾行不以列表符号开头才报——「Ability: X」「Topaz Crystal Hunter」这类
标题或名字行后面的英文是漏译的正文，不是被撕开的句子。`value` 只核对占位符值：先按序数、时长、倍率
规则换算，再要求每组数字在译文里出现同样多次；记录自己英文里的字面数字（`12:00 am-11:59 pm`、`5x`）
和词表整体翻译的值（`2X POWDER` → 双倍粉末）是译者做过的决定，不算丢失，`5m` 也不再被读成五百万。
`layout_overflow` 只在原文各行自身放得下、译文放不下时报告：英文本来就比聊天框宽的行原版照样折行，
更窄的中文不是回归。`checkTranslations` 会阻止引用本记录没有捕获的占位符。

新增分类沿用采集总开关、提示开关、异步写盘、区域暂存、去重和清空机制。关闭采集、离开空岛和断线只请求后台排空写盘；JVM 退出时的等待共用 30 秒截止时间，
不会在超时后回到客户端同步写盘。辅助别名索引各保留至多 16,384 项；逐出后的重复观测携带原始快照，
可重新分类并找回已有记录，不能只剩一个无法恢复的“重复”标记。`_capture.diagnostic` 下的
`original_lines`、`rendered_lines` 与 `records` 是同一次观测的具体证据，不是拼接 `observed` 得到的样本。

`./gradlew checkDiagnostics` 在所有目标上回放截图对应的原文、73 条独立采集颜色样本及故意损坏的记录，
验证检测、落盘、合并与清理。像素算术使用可控字宽，游戏中的字体资源和其他 Mod 组合仍需实机确认。

### 头顶通名与专名

Hologram 的明确职务语料可翻译绿色 NPC 名牌，不按颜色一刀切。非玩家活体实体及隐形盔甲架的
标准血条另走受限路径（「翻译生物名」关闭时整条跳过）：只有整个怪物名命中 `mob_name` 词表时才替换名字，等级、图标、血量与各段
实时样式原样保留；例如 `Glacite Mutt` 与 Tab 共用“极冰野狗”。玩家、掉落物、未知专名均不进入通用翻译。
动态血条在名字尚未翻译时也进入采集，血量变化沿用模板归并，不因动态而整行丢弃。此路径同样遵守服务器边界、总开关与原文键。

头顶文字采集只读取玩家 32 格内、由服务器元数据包登记的实体，按空间桶查找同列邻行；每次最多 12 行，并标注这只是空间邻近、不是已确认的段落。每条记录最多保留三个位置/区域场景，迟到的邻行可以补全快照，倒计时变化不额外占位。观测签名包含可见样式，因此纯颜色变化仍会重新诊断。`translate: false` 与 NPC 名单仅保留翻译决定，不再据此屏蔽采集。博物馆标签仍只借用离线目录确认过的物品名；排行、重铸和星级可复用同一路径，各段实时样式不变。

### 自检

```bash
./gradlew checkCapture
```

拿真实会话里的文本跑整条采集链路：颜色还原、模板归并、说话人识别、六类问题的分类、落盘目录结构。

### 把采集结果倒回去看

照着采集结果补完记录之后，下一个问题是「补对了没有」。采集文件里逐字保留了原文，
连颜色码和图标字形都在，所以直接拿它回放就行：

```bash
./gradlew replayCapture                    # 回放 logs/skyzh-capture 全部
./gradlew replayCapture -Pcapture=<目录>   # 只回放某个玩法 / 渲染面 / 单个文件
```

每一行都会连「现在渲染成什么样」一起打出来。这一步能抓到 `checkTranslations` 结构上抓不到的问题：
那个检查只知道语料对自己的说法，所以分段顺序写反了、手写的空格夹在两个汉字中间、
某个值忘了加进 `_shared/Terms.json`——这些都能通过检查，屏幕上却还是不对。在这里是一行输出的事。
`incomplete/` 与 `value/` 里的记录带着那次观测的整组原文行，回放时按 Tooltip 原样重跑同一套检查，
打印「已消除」或「仍报告」以及现在画成什么；`layout/` 要量字体，不回放。

## NEU 物品 Lore 整句

`GUI_Lore/` 对应独立的 `Surface.LORE`，只在 Tooltip 的物品名之后查找。
`LoreMatcher` 跨英文折行匹配完整句子，最长 12 行/2048 字符、不跨空行；只使用这一渲染面的
明确模板，不拿旧 ITEM 半句猜测后文。完整命中优先，未命中继续走旧翻译路径。
数值、图标与颜色仍通过 `TranslationEntry` 从原始组件搬运，最终由 `TextLayout` 量字折行。
物品名路径不查询 LORE，新技能标题因此不会改名；关闭翻译或处于原文模式时不读取 Tooltip 译文缓存。

`TextCapture.item` 使用相同的整句判定，已命中的句子在 `GUI_Lore` 分类检查 mixed/colour，
未知句子仍按原始行采集。不会修改 ItemStack，也不引入在线翻译或运行时 NEU 下载。

- `checkLore`：所有目标都执行，校验原始样本、改变英文断行后的匹配/颜色、独立手写期望、
  不跨空行/长度边界、保留物品名及采集诊断。
- `auditNeuLore -PneuItems=<items目录>`：仅开发工具，输出 `build/neu-lore-audit.json`。
  统计逐行匹配与整件全部含词行匹配，分别报告，不能拿属性行命中冒充整件完成。
  宠物 NEU 参数取值 10 是离线取样，不等于实测全部等级。
- `samples`/来源物品列表等仅供翻译和测试使用，现有精简器不会将它们打入 jar。

## 构建

```bash
./gradlew dist     # 三个 jar 都产出到 build/dist，产出前所有目标的检查都会跑一遍
./gradlew build    # 同样三个 jar，各自留在自己的 build/libs 里
```

需要 JDK 25。Minecraft 26.x 不再混淆，因此没有映射层，Mod 之间是普通依赖关系，
Loom 也不再有 `remapJar` 这一步。可安装文件由 `shadowJar` 生成：按目标内置并重定位 MoulConfig 4.8.0，合并其 access widener 与服务声明，另嵌套 Kotlin 标准库，无需玩家额外安装依赖。`jar` 只生成 `build/devlibs/` 下未重定位的开发文件，不可用于分发。

### 三个 Minecraft 版本，一套源码

| | jar | 声明的 Minecraft | 编译时用的 Mod Menu |
|---|---|---|---|
| `fabric-26.1/` | `SkyBlockZH-<版本>-Beta-Fabric-26.1.jar` | `>=26.1 <26.2` | 18.0.0 |
| `fabric-26.2/` | `SkyBlockZH-<版本>-Beta-Fabric-26.2.jar` | `>=26.2 <26.3` | 20.0.1 |
| `fabric-26.3/` | `SkyBlockZH-<版本>-Beta-Fabric-26.3.jar` | `>=26.3 <26.4` | 21.0.0 |

所有目标都编译 `src/main/`，并通过 `versionSourceDirs` 选择平台源码。26.1 使用 `src/mc26_1/`，
26.2 和 26.3 共用 `src/mc26_2/` 的 GUI 与 Mixin；26.1/26.2 使用 `src/glfw/` 读取鼠标状态，
26.3 使用 `src/mc26_3/` 的 SDL 适配。`ClientInput` 隔离底层输入接口，热键开关逻辑仍共用。
SDL 鼠标编号从 1 开始且使用位掩码，键盘使用物理扫描码；版本专用自检会验证这些差异。
所有目标的打包与检查都由 `gradle/target.gradle` 定义；`probe`、`auditLog` 等语料工具仅在最新目标注册。

GUI 的三处版本差异如下：

| 动了什么 | 26.1.x | 26.2 / 26.3 |
|---|---|---|
| 画 HUD 的类 | `Gui` | 从 `Gui` 里拆出来的 `Hud` |
| `SubmitNodeCollector#submitNameTag` | 末尾多一个 `double` | 没有 |
| 谁持有聊天框和屏幕栈 | `Gui#getChat`、`Minecraft#setScreen` | `Gui.hud#getChat`、`Gui#setScreen` |

最后一行是 `platform/ClientGui`，每个目标一份，方法签名相同。前两行是 `mixin/HudMixin`、
`mixin/HudScoreboardMixin` 和 `mixin/EntityRendererMixin`——**只有注解**；
它们被触发之后做什么，是 `hook/` 里的共享代码，只写一遍。

一个 jar 覆盖 26.1、26.1.1、26.1.2 全部三个版本：这个 Mod 碰到的每一个类，
在三个版本里的字节码完全一致。所有版本范围都设有上界，让 Fabric 只在受支持的 Minecraft 版本上加载对应 jar。
`require = 0` 允许注入点缺失，并不代表跨版本兼容。

### 怎么确认注入点还在

```bash
./gradlew checkMixinTargets     # 是 `check` 的一部分，所有目标都会跑
```

这是 `require = 0` 让人不得不做的检查。它把**编译产物**里的注解读回来——真正的 `@Mixin` 值、
真正的 `method` 列表、真正的 `At.target`——然后逐个去那个目标编译时用的 Minecraft 里查，
`@Shadow` 成员也查：那些不是 `require = 0`，对不上是在应用 Mixin 时直接崩，而不是安静地失效。
能编译只能证明这个 Mod 的源码自己跟自己一致，完全不能证明注入点还在。
见 `tests/check_mixin_targets.py`。

想拿现有产物去对一个当前没在编译的 Minecraft——`>=26.1 <26.2` 这个范围就是这么定下来的，
不是猜的：

```bash
./gradlew :fabric-26.1:build -Pmc26_1_version=26.1.2   # 用后面的补丁版本重新编译 26.1 这棵树
```
